VitaCoreX v209 functional/layout reset

What was broken
- The current build still had multiple generations of header/mobile/dock CSS active at the same time.
- Mobile menu behavior was unstable because several JS/CSS layers were controlling the same `.menu-btn`, `.mobile-nav`, and header state.
- The header geometry was conflicting between fixed/sticky/compact/hidden states.
- The dock sizing was still oversized and different CSS generations were fighting on mobile.

What I changed
1. Added a single final CSS architecture file: `assets/css/layout-stable.css`
   - Rebuilt only the affected systems: site header, desktop nav, mobile meta row, mobile menu, hero top spacing, and bottom dock.
   - Forced one compact desktop header model.
   - Forced one compact mobile header model.
   - Rebuilt the dock to: desktop one row, mobile three compact rows.
   - Reduced dead space, removed giant panel behavior, tightened button sizes.

2. Added a single final JS controller: `assets/js/layout-stable.js`
   - Replaced the live menu button node with a clean clone to strip conflicting earlier listeners.
   - Rebound exactly one mobile menu controller.
   - Added close-on-link, close-on-outside-click, close-on-escape, and desktop resize reset.
   - Neutralized old hidden-header state classes during scroll/resize.

3. Updated all HTML files
   - Loaded `layout-stable.css` after `styles.css`
   - Loaded `layout-stable.js` after `site.js`

Which bug each change fixes
- Mobile menu not opening reliably:
  fixed by replacing the menu button listener stack with one controller in `layout-stable.js`
- Header disorganized on desktop:
  fixed by canonical desktop header rules in `layout-stable.css`
- Header disorganized on mobile:
  fixed by canonical mobile meta row + toggle row + mobile nav rules
- Dock too large:
  fixed by new dock dimensions, row layout, icon sizing, and reduced body bottom padding
- Overlap / click failures:
  fixed by removing hidden/floating state interference and normalizing pointer/click zones

Verification status
- I verified the DOM structure and interaction logic path directly in the uploaded files.
- I also rebuilt the affected layout system so later legacy rules no longer control header/menu/dock geometry.
- I am not claiming unrelated sections were redesigned.
