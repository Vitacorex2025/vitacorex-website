VitaCoreX Emergency Recovery Report v246

Root cause
1. The duplicate UI was caused by responsive shell CSS, not by a double JS mount.
2. The HTML contains both desktop and mobile header/dock structures by design.
3. In assets/css/ui-shell.css, desktop default visibility rules were missing:
   - .vcx-header-mobile was not hidden by default on desktop
   - .vcx-dock-mobile was not hidden by default on desktop
4. As a result, on desktop the browser rendered both:
   - desktop header + mobile header
   - desktop dock + mobile dock
   This created:
   - duplicated bottom dock
   - duplicated Request Service CTA
   - broken header structure
   - mixed mobile/desktop layout state

What was checked
- No duplicate header or dock nodes were found in page HTML.
- No duplicate render function, DOM append loop, or repeated dock injection was found in ui-shell.js.
- site.js and ui-shell.js both already had single-boot guards:
  - window.__VCX_SITE_BOOTED__
  - window.__VCX_UI_SHELL__
- No MutationObserver / ResizeObserver append loop was present.

What was changed
1. assets/css/ui-shell.css
   - Added explicit desktop-default visibility rules:
     - show .vcx-header-desktop
     - hide .vcx-header-mobile
     - show .vcx-dock-desktop
     - hide .vcx-dock-mobile
   - Added an explicit @media (min-width: 901px) guard to preserve the same behavior on desktop.

2. assets/js/ui-shell.js
   - Added normalizeResponsiveShell()
   - This function force-enforces exactly one responsive shell at runtime:
     - desktop only above 900px
     - mobile only at 900px and below
   - It also closes mobile nav when returning to desktop.
   - Hooked this normalization into boot(), resize, and visibility recovery.

What guarantees single render now
1. CSS now defines a valid default desktop state.
2. JS now enforces the same state at runtime, even if cached CSS or partial asset mismatch occurs.
3. Existing global boot guards still prevent repeated controller boot.

Files changed
