# Phase 7B Report -- Chat Attachment and Image Handling

> Generated 2026-04-03 | Branch: `codex/phase2-safe-realign`
> Scope: Structured attachment handling for the floating chat widget,
>        including image preview, category classification, controlled
>        fallback messaging, and enhanced validation.

---

## Objective

Enhance the floating chat to properly handle file and image uploads:
1. Classify attachments as "document" or "image"
2. Show image preview thumbnails in chat
3. Provide honest, controlled fallbacks (no fake analysis)
4. Route to intake/review when appropriate
5. Clear validation error messages
6. Wire attachments into the convert-to-intake flow

---

## Changes Made

### 1. Backend: Attachment Service (NEW)

**File:** `vcx-api/app/services/chat_attachments.py` (~140 lines)

| Function | Purpose |
|----------|---------|
| `classify_attachment(filename, content_type)` | Returns "document" or "image" by extension, MIME fallback |
| `type_label(filename)` | Human-readable type: "PDF document", "JPEG image", etc. |
| `list_session_attachments(session_id)` | Reads `uploads/chat/{session_id}/`, returns metadata list |
| `build_attachment_summary(session_id)` | "2 files attached: contract.pdf (PDF document), photo.jpg (JPEG image)" |
| `attachment_acknowledgment(filename, category, type_label)` | Generates honest, category-aware bot response |

Category mapping:
- **Image:** .jpg, .jpeg, .png, .gif
- **Document:** .pdf, .doc, .docx, .txt, .md, .csv, .xlsx, .xls

### 2. Backend: Enhanced Upload Response

**File:** `vcx-api/app/routers/chat.py`

The `POST /api/legal-chat/upload` endpoint now returns three new fields:

```json
{
  "ok": true,
  "session_id": "...",
  "file_id": "uuid",
  "filename": "contract.pdf",
  "size": 102400,
  "content_type": "application/pdf",
  "category": "document",
  "type_label": "PDF document",
  "acknowledgment": "Document received: contract.pdf (PDF document).\n\nI cannot read..."
}
```

### 3. Backend: Session Attachments Endpoint (NEW)

**File:** `vcx-api/app/routers/chat.py`

```
GET /api/legal-chat/attachments/{session_id}
Rate limit: 30/minute

Response:
  { ok, session_id, count, attachments: [...], summary }
```

Returns all files attached to a session with metadata (file_id, filename,
category, size, type_label) and a human-readable summary.

### 4. Backend: Convert-to-Intake Attachment Wiring

**File:** `vcx-api/app/routers/chat.py`

The `POST /api/legal-chat/convert-to-intake` endpoint now:
1. Calls `build_attachment_summary(session_id)`
2. If files exist, appends summary to the `doc_hint` field
3. Intake form sees "Chat attachments: 2 files attached: ..."

### 5. Backend: Enhanced Models

**File:** `vcx-api/app/models/chat.py`

- `ChatUploadResponse`: added `category`, `type_label`, `acknowledgment`
- `ChatAttachment`: new model for attachment metadata
- `ChatAttachmentsResponse`: new model for session attachment listing

### 6. Frontend: Category-Aware Upload Display

## Controlled Fallback: No Fake Analysis

**Design principle:** The system never pretends to analyze file contents.

### Image response:
> Image received: photo.jpg (JPEG image).
>
> I cannot analyze images directly. If this image is relevant to your matter,
> please describe what it shows and I can help guide you.
>
> The image will be included if you convert to a structured intake.

### Document response:
> Document received: contract.pdf (PDF document).
>
> I cannot read document contents directly in chat. For full document review,
> consider our Contract Review service.
>
> This file will be included if you convert to a structured intake.

Both generated by `attachment_acknowledgment()` on the server, returned in
`ChatUploadResponse.acknowledgment`, and displayed by the widget.

## Risk Assessment

| # | Risk | Severity | Mitigation |
|---|------|----------|------------|
| 1 | Image preview uses objectURL (memory) | Very Low | Revoked on image load via onload handler |
| 2 | Large image preview slows rendering | Low | Max-height 160px with object-fit:cover; no full-size decode |
| 3 | Camera capture unsupported on some desktop browsers | None | Falls back to file picker (same as image upload) |
| 4 | list_session_attachments reads filesystem | Low | Only reads per-session dir; no path traversal (session_id from user) |
| 5 | Session directory may not exist | None | Returns empty list if dir missing |
