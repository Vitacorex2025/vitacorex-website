TECHNICAL REPORT v250 — emergency compatibility hotfix

Root cause:
1. The live HTML still exposes two shell branches in the same DOM:
   - desktop header + mobile header
   - desktop dock + mobile dock
2. That dual-shell HTML causes duplicated header structure, duplicated Request Service controls, duplicated bottom dock rows, and mixed desktop/mobile state.
3. I did not find a second append loop in the shell controller; the break is architectural in the shell layer itself.

What was removed / rolled back:
- Removed legacy shell blocks from the patched HTML pages:
  - <header class="vcx-header">...</header>
  - <div class="vcx-dock">...</div>
  - prior recovery shell containers, if present
- Neutralized all legacy shell selectors in assets/css/ui-shell.css

What was rebuilt:
- Rebuilt the header from scratch as a single injected shell
- Rebuilt the bottom dock from scratch as a single injected shell
- Replaced assets/js/ui-shell.js with a compatibility injector that:
  - removes legacy shell DOM
  - inserts exactly one header
  - inserts exactly one bottom dock
  - restores the mobile menu
  - preserves Request Service, WhatsApp, and Calendly links
- Added root fallback files:
  - .htaccess
  - index.php
  - index.htm

What guarantees single render:
- The HTML patch removes the legacy shell blocks from the main pages.
- ui-shell.js has a one-time global guard.
- ui-shell.js removes any prior injected hotfix shell before building.
- The injector creates exactly:
  - one [data-vcx-hotfix="header"]
  - one [data-vcx-hotfix="dock"]

Known limitation:

The package is verified at source/code level, and targets the exact dual-shell defect currently exposed by the live HTML.
