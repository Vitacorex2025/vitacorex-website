EMERGENCY SITE RECOVERY REPORT v249

Confirmed failure pattern
- The live site is still serving a broken shell state with duplicated header/dock behavior on the public root.
- The uploaded refactor branches introduced a dual-shell architecture: separate desktop and mobile header/dock blocks existed in the DOM at the same time.
- When the responsive visibility layer failed or stale root files/assets remained on the host, both shell branches could render together.

Exact root causes identified
1. Broken dual-shell architecture
   - Desktop and mobile shell blocks coexisted in HTML.
   - The layout depended on CSS visibility rules to hide one branch.
   - When those rules were not applied correctly, both branches rendered.

2. Deployment / root-entry residue risk
   - The public root and /index.html appear to behave like different versions.
   - That strongly suggests the host may still be serving an older root entry file or cached HTML/CSS/JS.
   - This explains why earlier shell patches did not fully replace the live broken state.

What was removed / rolled back
- Removed legacy shell markup from the main public HTML pages:
  - old header shell
  - old dock shell
  - old desktop/mobile split shell logic
- Removed dependence on the previous ui-shell runtime for rendering the active header/dock.
- Replaced legacy ui-shell.css and ui-shell.js with neutralizers so partial deployments cannot re-enable the old duplicate shell.

What was rebuilt
- Built a new single-render shell with unique classes:
  - one header
  - one mobile menu controller
  - one bottom dock
- Added new versioned assets:
  - assets/css/recovery-shell.v249.css
  - assets/js/recovery-shell.v249.js
- Added hard root-entry fallbacks:
  - index.htm
  - index.php
  - .htaccess forcing root to index.html and disabling HTML/CSS/JS caching

What guarantees single render now
- Public pages now contain exactly one new header and one new dock in HTML.
- Legacy shell blocks are removed from the public HTML pages, not merely hidden.
- Legacy shell CSS/JS files are converted into neutralizers, so an incomplete deploy cannot resurrect the old dual-shell UI.
- The root entry is forced toward index.html through .htaccess, with index.htm and index.php fallbacks included.

Important deployment note
- Upload the entire package to the host root.
- Delete or overwrite old root entry files on the host if they exist:
  index.php, index.htm, old cached index.html, old assets/css/ui-shell.css, old assets/js/ui-shell.js.
- Then clear hosting/CDN/browser cache.
