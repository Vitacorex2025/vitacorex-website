# VCX Contract Generator

> Phase 9 | 2026-04-03
> Product: VCX Contract Review Desk -- Generation Mode

## Overview

The Contract Generator allows users to create professional draft contract
documents through a guided questionnaire. It is accessed via the
"Generate New Contract" tab on the Contract Review Desk page.

The system generates valid DOCX files with standard clauses, clear
review disclaimers, and editable structure -- ready for attorney review
and customization in Microsoft Word.

---

## User Flow

1. User navigates to `/app/vcx-contract-review/`
2. Clicks "Generate New Contract" tab
3. Selects one of 4 contract types
4. Fills in questionnaire fields (party names, terms, etc.)
5. Clicks "Generate Contract"
6. System generates DOCX via backend API
7. Download link appears with filename and size
8. User downloads and opens in Word

## Generated Document Structure

Every generated DOCX contains:

1. **DRAFT header** -- Red "DRAFT -- NOT LEGAL ADVICE -- FOR REFERENCE ONLY"
   on every page (8pt bold red)
2. **Disclaimer page** -- Full legal notice before contract content:
   "This document was generated by an automated system and does NOT
   constitute legal advice..."
3. **Contract title** -- Centered, VCX brand navy
4. **Preamble** -- Party identification with effective date
5. **Recitals** -- Purpose and consideration
6. **Numbered articles** -- Type-appropriate clauses (Article 1, 2, 3...)
7. **Signature blocks** -- Party name, title, date fields
8. **Footer disclaimer** -- Gray 7pt: "Generated by VitaCoreX -- Not legal advice"

### Document Styling
- Font: Calibri 11pt
- Headings: VCX brand navy (#173A63)
- Margins: 1.25" left/right, 1" top/bottom
- Alignment: Justified
- File format: .docx (Office Open XML)

## API Endpoints

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/contracts/types` | List available contract types |
| POST | `/api/contracts/generate` | Generate contract from questionnaire (rate: 10/min) |
| GET | `/api/contracts/{id}/download` | Download generated DOCX file |

### POST /api/contracts/generate

**Request body** (JSON):
```json
{
  "contract_type": "nda",
  "party_a_name": "Acme Corp",
  "party_b_name": "Widget Inc",
  "effective_date": "2026-04-15",
  "governing_state": "Florida",
  "term_months": 12,
  "purpose": "Evaluation of potential business partnership"
}
```

**Response** (201):
```json
{
  "ok": true,
  "contract_id": "abc123...",
  "contract_type": "nda",
  "contract_label": "Non-Disclosure Agreement (NDA)",
  "filename": "VCX_Non-Disclosure_Agreement_NDA_abc12345.docx",
  "size_bytes": 15432,
  "download_url": "/api/contracts/abc123.../download",
  "disclaimer": "This document was generated by an automated system..."
}
```

## Frontend Architecture

### Files
- `app/vcx-contract-review/index.html` -- Mode tabs + type picker + form + result panel
- `assets/js/vcx-contract-review.js` -- Tab switching, form building, API calls, download rendering
- `assets/css/vcx-contract-review.css` -- All generator styling (scoped, no global impact)

### Design Decisions
- Tab-based mode switching (Analyze vs Generate) -- preserves existing analyzer UX
- Card-based type selector (not a dropdown) -- visual, discoverable
- Dynamic form fields (JS-rendered) -- type-specific without page reload
- Two-column grid layout (collapses on mobile)
- Download via `<a download>` -- native browser download, no popup
- All styles in namespaced CSS (no global file modifications)

---

## Disclaimers

The generator includes disclaimers at every layer:

1. **UI intro text**: "intended as starting points only"
2. **DOCX header**: "DRAFT -- NOT LEGAL ADVICE -- FOR REFERENCE ONLY"
3. **DOCX page 1**: Full legal notice
4. **DOCX footer**: "Not legal advice -- Consult licensed counsel"
5. **API response**: `disclaimer` field in JSON
6. **Download panel**: Disclaimer text shown below download button
7. **Page footer**: Standard VitaCoreX "not a law firm" disclaimer

No generated content is presented as final or legally binding.

  numeric fields validated for positive values

  (rejects invalid types at Pydantic validation layer)
